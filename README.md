# ShieldDNS for Android

桌面版 [ShieldDNS](https://github.com/sayaxia/ShieldDNS) 的安卓版本：本地 DNS 过滤，不需要 root，不接管除 DNS 以外的任何流量。

## 系统要求

- Android 8.0（API 26）及以上
- 安装包为 `arm64` / `x86_64` 通用，纯 Kotlin，无 native 库

## 它做什么

安卓不允许普通应用监听 53 端口，所以这里用 `VpnService` 建一个**只有 DNS 走它**的本地 VPN：

- 虚拟接口地址 `10.111.0.2/32`，把 `10.111.0.1` 注册成系统 DNS，只给这个地址加一条 `/32` 路由；
- 应用发出的 DNS 查询（UDP:53 与 TCP:53）进来后解析 QNAME，命中规则就**本地造应答**（NXDOMAIN，或 `0.0.0.0` 的一条 A 记录），不命中就经受 `protect()` 保护的 socket 转发给上游，再把应答写回 tun；TCP 查询由内置的最小 TCP 栈封装回客户端；
- 其余所有流量（网页、视频、下载）**完全不经过 VPN**，不额外绕一层，也不影响网速。

另有一个可选的 **SNI 增强拦截**（默认关闭），它会把 VPN 收紧成「只接管单个应用」，和通用 DNS 过滤**互斥**：

- 打开后 VPN 用 `addAllowedApplication` 只让一个包进 tun（默认 `com.phoenix.read`，红果免费短剧；包名写死在应用里，界面暂不提供修改入口），
  **其它应用的流量连同它们的 DNS 完全不经过本应用**；
- 只对被接管的应用接管 TCP:443，在 TLS 握手（ClientHello）里读出明文域名，用于它走 HTTPDNS 拿 IP 直连、DNS 层根本看不见的场景；
  命中广告域名直接断开该连接。不接管 UDP，不做中间人解密。

所以两种模式只能二选一：

| 想要的 | 怎么做 | 覆盖范围 |
| --- | --- | --- |
| 全设备通用 DNS 过滤 | 关闭「启用增强拦截」 | 所有应用的 DNS（UDP/TCP 53） |
| 对单个应用做 DNS + SNI 双层 | 打开「启用增强拦截」 | 仅该应用的 DNS 与 TCP:443，其它应用不受保护 |

> 增强模式下 DNS 层只作用于被接管的那一个应用，**不是全设备**。想要全设备又要 SNI，需要把所有应用的 TCP 都拉进 tun（等于全局代理，耗电与兼容性代价大），本应用没这么做。

启动即「待命」：不自动接管，需要你在概览页打开开关并授权一次 VPN。
内置了一份针对字节系短剧广告的规则，在「过滤订阅」里置顶显示、不能拖动也不能删除，可整条关掉，也可点「更新」拉最新版。

内置订阅的地址（写死在应用里，界面只能改名和开关，不能改 URL）：

```
https://cdn.jsdelivr.net/gh/sayaxia/ShieldDNS-for-Android@main/rules/default-rules.txt
```

- 规则文件本身在仓库 [`rules/default-rules.txt`](https://github.com/sayaxia/ShieldDNS-for-Android/blob/main/rules/default-rules.txt)，64 条，用 `# == [dns] ==` / `# == [sni] ==` 分段；
- 镜像：`https://fastly.jsdelivr.net/gh/sayaxia/ShieldDNS-for-Android@main/rules/default-rules.txt`、`https://raw.githubusercontent.com/sayaxia/ShieldDNS-for-Android/main/rules/default-rules.txt`；
- 拉不到（无网、镜像挂）时回退到随包副本 `assets/default-rules.txt`，离线照样拦；
- 下载结果缓存在应用私有目录 `files/filters/builtin.txt`；
- 另有 `rules/hongguo-adblock.txt`（15 条纯 DNS），可当普通订阅手动添加。

这条订阅是全网共享的，所以正文必须能验签：规则文件旁边有一份同名的 `default-rules.txt.sig`
（ECDSA P-256 + SHA-256），公钥固定在 APK 里。下载时会同时取正文与签名，**验不过就拒收**——
正文不写缓存，继续用随包副本。CDN 缓存被改、网络中间人插一手、仓库写权限被盗，都下不出能用的规则。
本地缓存文件同样要验签才读，旧版本留下的未签名缓存会自动作废回退到 assets。
改完规则记得跑 `bash scripts/sign-rules.sh` 重新签名，正文与签名必须一起提交。

也可以自己加订阅或自己写规则。规则按来源分层：自定义规则 > 关键域名放行 > 订阅（按列表顺序从上到下）> 内置策略。

「关键域名放行」是一层内置兜底（`CriticalHosts.kt`）：微信登录/消息/支付、支付宝网关、系统网络探测共 13 个域，
任何订阅或内置规则误伤到它们都会被放行，避免一条错规则把用户设备搞成"没网"。想连这些也拦，写进自定义规则即可
（自定义优先级更高）。

## 页面

| 页面 | 内容 |

| 概览 | 状态与开关、监听地址、生效规则数、订阅更新时间、更新全部订阅；查询总数 / 已拦截 / 拦截率 / 缓存命中 / 生效规则 / 运行时长；最近 8 条查询 |

## 规则语法

复刻桌面版支持的 AdGuard 子集：

```
||ads.example.com^        阻断该域名及所有子域
@@||ok.example.com^       例外（优先于阻断）
example.com               裸域名，同样覆盖子域
0.0.0.0 tracker.example   hosts 写法
127.0.0.1 beacon.example  hosts 写法
```

支持 `*` 通配，位置随意：`||*-reading-ad.qznovelvod.com^` 匹配 `v95-aw-reading-ad…`，`||ads*.adcdn.com^` 匹配 `ads3.adcdn.com`。

不支持、会被跳过的写法：`##` 外观规则、正则（`/…/`）、`[dns]` / `[sni]` 分段标记；`$options` 只取域名部分、选项本身忽略。
自定义规则页会逐行检查这些写法，把无效行的行号和原因列出来，不会再静默丢弃。
匹配方式是「按标签逐级截断查哈希表」，几万条规则也是常数级。

## 使用

1. 安装 APK。
2. 打开应用 → 概览页打开开关 → 系统弹出 VPN 授权 → 允许。
3. 到「过滤订阅」加一条规则源（例如 AdGuard DNS filter 的 `https://…/adguard.txt`），点更新。
4. 想要开机后一直生效，可在系统设置里把 ShieldDNS 设为「始终开启的 VPN」。

## 已知限制

- 处理 **UDP:53 与 TCP:53**；只有发往本地 DNS 地址 `10.111.0.1` 的 DNS 流量会进 VPN，不止「命中的查询」——未命中的也要过一遍规则判断，再由受保护的上游 socket 转发。其它流量不进 VPN。
- 通用 DNS 过滤与 SNI 增强拦截互斥：增强模式下 VPN 只接管一个应用，其它应用的 DNS 也不经过本应用。要全设备过滤就关掉增强拦截。
- 不处理 DoT(853) / DoH。开了系统的「私人 DNS」时查询不走这里，等于绕过本应用；要用本应用请先关掉私人 DNS。
- 拦截靠伪造应答（NXDOMAIN 或 0.0.0.0），不修改系统 DNS 设置，卸载/关闭开关即刻恢复。
- 上游默认跟随系统：只取底层网络（显式排除本应用自己的 VPN 网络，永远不会把 `10.111.0.1` 当上游），按「有线 > WLAN > 蜂窝」排序取系统下发的 IPv4 DNS；切网、开关 WLAN/蜂窝都会自动刷新（网络回调 + 每 5 秒兜底重算），拿不到时回退 `223.5.5.5` / `8.8.8.8`。

## 隐私

- 查询日志只存在本机内存里，最多 2000 条，关掉开关或退出应用就没了，不会上传。
- 订阅规则、配置存在应用私有目录（SharedPreferences）。
- VPN 只把 DNS 收进本地接口，其它流量不经过本应用，也不做任何转发记录。
